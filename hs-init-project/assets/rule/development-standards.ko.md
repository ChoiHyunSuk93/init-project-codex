# 개발 기준 규칙

## 우선순위

1. 사용자 요구사항과 관찰 가능한 정확성
2. 기존 구조와 프로젝트 관례
3. 안전성, 데이터 무결성, 회귀 방지
4. 단순성, 유지보수성, 검증 가능성

## 필수 원칙

- 기존 구현과 공용 abstraction을 먼저 찾고 중복 구현을 피한다.
- 변경 범위를 요구사항에 필요한 최소로 유지한다.
- 책임을 명확히 나누고 이름에서 의도와 동작이 드러나게 한다.
- 환경, 경로, 비밀값, 정책값을 코드에 임의로 hardcode하지 않는다.
- 지원하지 않는 상태는 fail fast하고 silent fallback으로 숨기지 않는다.
- 현재 필요하지 않은 확장 지점이나 설정을 미리 만들지 않는다.
- 실패 원인을 확인할 수 있는 오류와 관찰 가능성을 제공한다.
- 테스트하기 어려운 전역 상태와 숨은 side effect를 피한다.

동작하는 것처럼 보여도 위 원칙이나 프로젝트의 더 강한 local rule과 충돌하는 구현은 올바른 완료로 보지 않는다.

## 변경 전후

- 변경 전 관련 call site, public interface, 데이터 경계와 검증 경로를 확인한다.
- 변경 후 가장 가까운 자동 검증을 실행하고 실행하지 못한 항목과 이유를 보고한다.
- unrelated 사용자 변경은 보존한다.
