# 프로젝트 초기화 워크플로

## 목적

`hs-init-project`로 신규 또는 기존 저장소에 문서화된 agent 작업 구조를 만들고, template 복사에 그치지 않고 실제 프로젝트 사실을 반영한다.

## 1. 저장소 확인

- 언어, `codex|claude|both` target, fresh/existing mode, README 정책을 정한다.
- existing mode에서는 root/local instruction, README, overview, source area, manifest/config, runtime entrypoint, tests, automation과 기존 docs를 확인한다.
- `--inspect` 결과는 충돌과 탐색을 위한 보조 정보이며 실제 source 분석을 대신하지 않는다.

```bash
sh hs-init-project/scripts/materialize_repo.sh --root <project-root> --inspect
```

## 2. 초기 구조 생성

먼저 `--dry-run`으로 생성·갱신·보존·충돌 경로를 확인한다.

```bash
sh hs-init-project/scripts/materialize_repo.sh \
  --root <project-root> \
  --language ko \
  --target both \
  --project-mode existing \
  --readme-mode preserve \
  --dry-run
```

충돌 정책을 정한 뒤 `--dry-run`을 제거한다. 기존 의미 있는 문서는 `--preserve <path>`로 보호하고, 명시적으로 교체할 경로만 `--overwrite` 대상에 포함한다.

## 3. 실제 내용 반영

existing mode에서는 대표 source를 직접 읽어 다음을 확인한다.

- runtime entrypoint와 주요 module 책임
- manifest, workspace, dependency, build/task 설정
- 실제 실행·빌드·테스트 명령
- 대표 test와 검증 계층
- 기존 guide, architecture, 운영 문서와 authoritative 위치

확인 결과를 `PROJECT_OVERVIEW.md`, `docs/guide/README.md`, `subagents_docs/roadmap.md`와 관련 rule에 반영한다. `HS_INIT_SEMANTIC_TODO`를 단순 삭제하지 말고 관찰 또는 사용자 확인 사실로 교체한다. 명령은 정의 파일을 찾은 경우에만 기록한다.

## 4. 작업 기록

- 오래 유지되는 요구사항은 `PROJECT_OVERVIEW.md`에 둔다.
- phase 상태와 완료 gate는 `subagents_docs/roadmap.md`에 둔다.
- 중간 이상 작업, work-sharing, 여러 handoff, 독립 검증은 `subagents_docs/cycles/<NN>-<slug>.md`에 append-only `Planner vN`, `Generator vN`, `Evaluator vN` section으로 남긴다.
- delegated agent는 공통 기록을 직접 수정하지 않고 결과를 반환하며 main agent가 header, roadmap과 최종 내용을 통합한다.
- 검증이 `PASS`된 실질 변경은 가장 가까운 `docs/implementation/<category>/NN-name.md`에 새 이력으로 남긴다.

## 5. 완료 검증

```bash
python3 hs-init-project/scripts/validate_materialized_repo.py \
  --root <project-root> \
  --project-mode existing
```

검증기는 필수 문서와 작업 기록 진입점, unresolved marker, roadmap phase 구조, Markdown link를 검사한다. existing mode에서는 generated harness 바깥의 실제 저장소 상대 경로가 overview 근거에 포함되어야 한다.

검증 통과는 형식적 하한선이다. 최종 보고 전에 문서 내용이 실제 읽은 source/config/test/docs와 일치하는지 다시 확인한다.
